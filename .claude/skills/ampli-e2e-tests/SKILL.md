# E2E-тесты Ampli

Тесты пишутся от поведения продукта и норм РБ, а не от реализации. Тест должен падать, если сломается то, что увидит электрик.

## 1. Карта перед написанием

1. Прочитай `PROJECT_CONTEXT.md`, `playwright.config.ts` и список `e2e/*.spec.ts`.
2. Составь карту экранов: шапка, вкладки (`src/app`), окна (`src/ui`), печать (`PrintMode`), обучение, ссылки `#p=`, `#e=`, `#o=`.
3. Для каждого экрана отметь: есть ли spec, какие действия пользователя не покрыты, есть ли проверка в обоих профилях (`phone` Pixel 7 и `desktop` 1366x860) и в тёмной теме.
4. Отдельно отметь элементы без доступного имени или роли: это первые кандидаты на доработку разметки, а не на `data-testid`.

## 2. Селекторы

- Порядок выбора: `getByRole` с `name`, `getByLabel`, `getByText` для видимого текста, и только потом `data-testid`.
- Тексты интерфейса русские, сверяй их по исходникам, не угадывай.
- Никаких CSS-классов, `nth-child`, XPath и привязки к структуре DOM.
- Если элемент нельзя найти по роли и имени, это баг доступности: сообщи о нём.

## 3. Как писать тест

- Один сценарий пользователя на тест: ввести приборы, получить группы, проверить автомат и сечение, распечатать.
- Ожидаемые числа берутся из норм (ТКП 339-2022, СН 4.04.01-2019, ПУЭ 1.3.4), а не из текущего вывода приложения. Пункт нормы указывается в названии теста, не в комментарии.
- Только веб-первые ожидания: `expect(locator).toBeVisible()`, `toHaveText`, `toHaveValue`. Никаких `waitForTimeout`.
- Состояние готовят через интерфейс или через `localStorage`/IndexedDB в `addInitScript`, как в соседних spec.
- Скачивания проверяй через `page.waitForEvent('download')`, имя файла с кириллицей.
- Печать: `page.emulateMedia({ media: 'print' })` и проверка видимых блоков.
- Тёмная тема: `page.emulateMedia({ colorScheme: 'dark' })`.
- Доступность: `@axe-core/playwright` в обеих темах, как в `e2e/a11y.spec.ts`.
- Тест не должен зависеть от порядка запуска: `fullyParallel: true`.

## 4. Слепые зоны, которые проверить в первую очередь

- Импорт и экспорт JSON, резервная копия, восстановление, лимит 32 МБ, битые файлы.
- Ссылки `#p=` и `#e=`: открытие, слишком большая ссылка, старая версия схемы.
- Печать всех документов: схема А3, спецификация, смета, акты, протокол, паспорт, карта проводки.
- Режим «Частный дом» и трёхфазный ввод.
- Узкие экраны 320 px и альбомная ориентация.

## 5. Проверка теста

1. Прогони новый spec: `npx playwright test e2e/<file> --trace off`.
2. Убедись, что тест падает при реальной ошибке: временно сломай проверяемое поведение или ожидаемое значение, тест должен стать красным. Верни как было.
3. Прогони трижды подряд (`--repeat-each=3`), чтобы исключить нестабильность.
4. Перед PR: `npm run check`.

## Правила проекта

- Комментариев в коде нет.
- Имена файлов `e2e/<сценарий>.spec.ts`, имена тестов по-русски, описывают поведение.
- Ветка `test/<что-проверяем>`, коммиты на английском.
