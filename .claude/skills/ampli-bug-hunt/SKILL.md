# Поиск багов в Ampli

Задача: найти реальные ошибки и доказать каждую падающим тестом. Код продукта не правится, правки делаются отдельно через `superpowers:systematic-debugging` и `superpowers:test-driven-development`.

## 1. Разбиение на участки

Прочитай `PROJECT_CONTEXT.md` и раздели проверку на участки:

| Участок | Где | Источник истины |
| --- | --- | --- |
| Ток, автомат, сечение | `src/core/calc.ts`, `norms.ts` | ТКП 339-2022, ПУЭ 1.3.4 |
| Потеря напряжения | `calc.ts` | СН 4.04.01-2019: 3 % свет, 5 % прочее |
| УЗО, дифавтоматы, УЗИП, УЗДП | `protection.ts` | ТКП 339-2022, ГОСТ IEC 61008-1, 61009-1 |
| Частный дом | `house.ts` | Принятые решения в `PROJECT_CONTEXT.md` |
| Документы | `spec.ts`, `acts.ts`, `protocol.ts`, `passport.ts`, `report.ts` | ГОСТ 21.613-2014, СН 1.03.04-2020 |
| Данные | `migrate.ts`, `share.ts`, `links.ts`, `src/store` | Схема данных, лимиты |
| Интерфейс | `src/ui`, `src/app` | Поведение на телефоне и компьютере, обе темы |

## 2. Как искать

- Ожидаемый результат выводи из нормы или из записанного решения, а не из кода.
- Ищи границы: 0, отрицательные числа, пустые строки, ровно на пороге (90 % загрузки, 63 А, 7,4 кВт, 40 А для УЗО 10 мА, 0,5 Ом, 30 Ом), очень большие проекты.
- Ищи несогласованность: одно и то же число на щитке, в спецификации, смете, схеме А3 и паспорте.
- Ищи потерю данных: файл, ссылка, резервная копия, миграция старой схемы.
- Ищи враждебный ввод в импорте и ссылках: битый JSON, огромные массивы, лишние поля, HTML в названиях.
- Для свойств используй fast-check, как в `src/test/core/calc-properties.test.ts`.

## 3. Подтверждение

Каждый кандидат в баги подтверждается:

1. Минимальный тест в `src/test/core/` или `e2e/`, который падает сейчас.
2. Запуск: `npx vitest run <файл>` или `npx playwright test <файл> --trace off`.
3. Если тест проходит, это не баг: убери кандидата из отчёта.

## 4. Отчёт

Для каждого подтверждённого бага:

- Где: `файл:строка`.
- Что ожидалось и по какому пункту нормы или решению.
- Что получено, с выводом теста.
- Шаги воспроизведения для электрика.
- Важность: нарушение нормы в расчёте, потеря данных, неверный документ, интерфейс.

Неподтверждённые подозрения выноси отдельным списком «Нужно сверить», особенно всё, что зависит от СП 4.04.04-2023 и табл. 4.4.47–4.4.48 ТКП 339-2022.

## Правила проекта

- Комментариев в коде нет.
- Падающие тесты на найденные баги идут в ветку `test/<участок>-bugs` и в PR помечаются как ожидаемо красные до исправления, либо через `it.fails` до отдельного PR с исправлением.
- Отчёт и PR на русском, коммиты на английском.
