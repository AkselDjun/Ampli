# Контекст проекта Ampli

Короткая выжимка того, что нужно знать перед любой задачей в репозитории. Подробности о возможностях и запуске в [README.md](README.md), история версий в [CHANGELOG.md](CHANGELOG.md). Файл обновляется вместе с решениями, которые меняют правила ниже.

Состояние на 11 ноября 2026, `main` после PR #44, версия `0.2.3`.

## Цель

Ampli помогает электрикам Беларуси собрать щиток квартиры или частного дома: от списка приборов до расчёта по нормам, схемы А3, спецификации, сметы, актов и протокола замеров. Ближайшая цель: довести продукт до MVP и выйти в прод. Пока MVP не достигнут, версии остаются в диапазоне 0.x.

- Прод: https://akseldjun.github.io/Ampli/ (GitHub Pages)
- Сервера нет: расчёт в браузере, данные на устройстве, проект передаётся файлом JSON или ссылкой `#p=`
- Результат расчёта предварительный, это написано в интерфейсе и в отчётах

## Правила работы

- Общение и описания PR на русском
- Комментариев в коде не оставлять
- Нигде не упоминать, что код или тексты подготовлены автоматически
- Коммиты на английском, автор AkselDjun, без служебных строк в конце сообщения
- Имена веток на английском и понятные по смыслу: `feature/private-house-mode`, `fix/calc-rcd-breaker-margin`, `docs/...`
- Каждое изменение идёт отдельным PR в `main`; перед пушем `npm run check`, при изменении сборки ещё `npm run build && npm run size`
- Если несколько PR сливаются подряд, после слияния проверить `main`: так сломался `main` между #41–#43 и чинился в #44

## Стек

- React 19 с React Compiler, TypeScript 5, Vite 8, `vite-plugin-pwa`
- Единственные runtime-зависимости: `react`, `react-dom`, `fflate` (сжатие ссылок)
- Тесты: Vitest 5 (happy-dom, fast-check, Testing Library), Playwright с axe
- Линтеры: ESLint, Stylelint
- Node.js 22 и новее, версия для CI в `.nvmrc`

```text

  store/                 редьюсер, IndexedDB, фото, прайсы, библиотека, резервные копии
  app/                   шапка, вкладки, навигация, стек окон
  ui/                    компоненты React, окна, печать
  features/onboarding/   модель, раскладка и хранение обучения
  styles/                токены дизайн-системы и стили
  test/                  модульные тесты; isolated/ для тестов с vi.mock

scripts/                 size.mjs (бюджет сборки), release.mjs
```

Границы слоёв проверяет `src/test/architecture/boundaries.test.ts`: `core` не импортирует `app`, `store` и `ui`; `store` не импортирует `app` и `ui`; модель обучения не зависит от React; экран обучения грузится только лениво.

## Принятые решения

- **cos φ и «Не одновременно» у приборов вместо Кс и cos у групп** (PR #41). Поля `kc` и `cos` у групп удалены, старые проекты очищаются при загрузке. У кондиционеров, насосов и компрессоров cos φ по умолчанию 0,8. Из приборов с отметкой «Не одновременно» в расчёт идёт самый мощный
- **УЗО без скачка на 32 А** (PR #41). Уставка 30 мА, в мокрых помещениях 10 мА, 100 мА автоматически не ставится. Утечка оценивается как 0,4 мА/А, замечание даёт только замер. УЗО 10 мА не больше 40 А, иначе помещение делится на несколько УЗО
- **Запас по автомату** (PR #41). Параметр сети, по умолчанию 1. Стиральная, сушильная, посудомоечная машина и водонагреватель получают не меньше 16 А. Загрузка выше 90 % подсвечивается
- **Ввод, поднятый селективностью** (PR #41). Проверка называет группу, из-за которой вырос вводной автомат, и предлагает разделить её или перейти на три фазы
- **Марка кабеля групп** (PR #41): ВВГнг(А)-LS, FRLS или NYM для схемы, спецификации и сметы
- **Режим «Частный дом»** (PR #43). Выбор объекта в «Параметрах сети». Ввод СИП-4 от опоры (потеря не больше 2 %, минимум 16 мм²), разделение PEN, повторное заземление (больше 30 Ом ошибка), УЗИП тип 1+2, уличные группы под УЗО, котёл на отдельной группе, предупреждение о городской петле меньше 0,5 Ом. Основной расчёт групп не меняется, всё лежит в `house.ts`
- **Обучение** (PR #40). 9 шагов в трёх главах (Расчёт, Монтаж, Документы), подсветка конкретного элемента, продолжение с места остановки, финальный экран создаёт проект «Мой объект». Код обучения в отдельном чанке
- **Интерфейс на телефоне** (PR #42). Компактная шапка до 560 px, кнопка «Номера по порядку», полоса загрузки автомата в списке, ввод замеров на щитке с клавиатуры, подсказки глав при первом открытии разделов
- **Хранение**. Проекты в IndexedDB `ampli-projects` по записи на проект, текущий проект дублируется в `localStorage` для быстрого старта, фото в `ampli-photos`. Резервная копия напоминается раз в неделю
- **Дизайн-система**. Цвета, шрифты, отступы и анимации только через токены `src/styles/tokens.css`; голые цвета запрещены линтером и тестом. Правила в [docs/design-system.md](docs/design-system.md)
- **PWA выключен** флагом `PWA_ENABLED`. Пока флаг выключен, ранее установленный service worker удаляется

## Качество и CI

| Проверка | Порог |
| --- | --- |
| Покрытие Vitest | не ниже 90 % по строкам, веткам и функциям |
| Бюджет сборки (gzip) | самый большой JS 100 kB, CSS 25 kB, всё вместе 290 kB (`scripts/size.mjs`) |
| Lighthouse | производительность от 85, доступность от 95, лучшие практики от 90; LCP до 3 с, TBT до 400 мс, CLS до 0,1 |
| Playwright | профили Pixel 7 и компьютер, axe в обеих темах |

- Сборка после #43 весит 286,2 kB, запас до бюджета около 4 kB. Новые крупные функции лучше выносить в ленивые чанки
- Деплой на GitHub Pages после зелёного CI на `main`
- Релизы автоматически по понедельникам в 09:00 по Минску: до 2000 изменённых строк patch, больше minor

## Открытые вопросы

- Сверка с СП 4.04.04-2023: нужен текст документа
- Множитель 1,5 для сопротивления петли при нагреве не подтверждён нормой, помечен как инженерный запас
- PWA выключен: перед выходом в прод решить, возвращать ли офлайн-режим, и выяснить причину отключения
- Номер схемы данных есть (`SCHEMA = 1` в `src/store/storage.ts`), но цепочки миграций нет: старые проекты приводятся к текущей модели при загрузке
- Производительность больших проектов (100+ групп): в «Отчёте» рисуются все вкладки сразу, на телефоне рисуются скрытые колонки
- В `e2e/data-integrity.spec.ts` 4 сценария нестабильны локально: имя скачанного файла и тайм-аут палитры

Технические планы и замеры: `architecture/tech-roadmap.md` и `architecture/ui-performance-review.md` в файлах проекта.
